# Phase 1 的 2.10 db1 基线校准记录

> 日期：2026-04-11  
> 范围：仅服务于 `Phase 1` 页面层收口，不扩展到 db2/db3 全量重构。  
> IDA 基线：`D:\AVEVA\Everything3D2.10\core.dll`

## 1. 本轮校准目的

当前仓内 `page_manager` / `writer` 的收口工作，需要一个**稳定的 2.10 真值**来约束语义。此前会话曾短暂使用 3.1 的 `core.dll.i64` 观察流程，但 3.1 结果只可辅助理解，**不可直接作为地址基线**。

本轮通过 `ida-pro-mcp` 切换并确认了 2.10 IDB，后续 `db1` 写路、harness 设计、FFI 绑定都应以本文和 `ida_exports/README.md` 为准。

## 2. 已确认的 2.10 关键函数

## 3. 语义校验结论

### 3.1 `db1_get_page`

- 反编译与字符串均显示 `db1_get_page` 同时携带 `dbno / pageno / extno` 语义，而非仅 `page_no`。
- 关键字符串包含：
  - `GET_PAGE: set dbno %d, pageno %d,extno %d in pfno %d`
  - `Read dbno %d, blk asked for %d (type %d), extno %d,tok %d,address %d`
- 调用链中可见：
  - `db1_read_page`
  - `db1_plu_add_entry`
  - `db1_get_page_frame`
- 结论：
  - Rust 侧 `ext_no` 不能只作缓存键，必须进入 I/O 接口语义。
  - prefetch 可以先保留简化实现，但接口上必须保留 `ext_no`。

### 3.2 `db1_update_page`

- 反编译显示该函数并非单纯“打脏位”，而是带有当前 db 校验、是否可更新检查，以及必要时的 Copy-on-Write / 新页分配路径。
- 可见关键调用：
  - `db1_page_may_be_updated`
  - `db1_get_new_page`
  - `db1_plu_add_entry`
  - `db1_plu_remove_entry`
- 关键字符串包含：
  - `Attempt to update a page not in the current db`
  - `db1_update_page should be dealing with 2 temp pages`
- 结论：
  - Rust 当前 `mark_dirty` 只是最小语义映射，还不是完整的 `db1_update_page`。
  - 但就 `Phase 1` 而言，至少要先保证 dirty 页不会被静默丢弃，并为后续 COW 留出接口。

### 3.3 `db1_write_page`

- 反编译与字符串均明确存在 `extno` 和缓冲批写语义。
- 关键字符串包含：
  - `WRITE_PAGE:temp_file_size %d, pgno %d, extno %d,pfno %d`
  - `Writing %d buffered pages from block %d`
  - `Dbno is %d, extno is %d`
- 结论：
  - Rust 侧 `flush_dirty_pages` 维持“按页排序 + 分批 flush”的实现方向是合理的。
  - 本轮不要求一比一复刻 core.dll 的完整缓冲结构，但必须避免“writer 旁路直写绕过 page manager”。

## 4. 对本轮代码收口的直接约束

- `ensure_capacity` 不得在“缓存已满且页面全锁”时空转，必须显式报错。
- `read_page_from_file` / `write_page_to_file` 必须显式接收 `ext_no`。
- 在多扩展物理路由尚未完成前：
  - `ext_no == 0/1` 可继续映射到当前单文件；
  - 其余 `ext_no` 必须报“未实现”，禁止静默写入同一 offset。
- `allocate_page` / `commit_session` 不能再绕开 `page_manager`。
- `commit_session` 不得再写死 `index_root(0)`。

## 5. 后续使用规则

- 若要继续扩展到 harness/FFI，先参考 `ida_exports/README.md`，确保仍在 2.10 IDB 下。
- 若要记录更多 db1/db2/db3 地址，请优先补到 `ida_exports` 导出物中，不在代码里硬编码 3.1 地址。
- `Phase 1` 未完全收口前，不建议进入 B+ 树 split 或 `PdmsEngine` 总入口整合。
