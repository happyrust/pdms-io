# E3D/PDMS 数据库底层页面管理器 (db1) 分析报告

## 1. 概述

通过对 `core.dll` 的逆向分析，我们识别并确认了负责 PDMS/E3D 数据库文件操作的核心底层驱动层——**db1 页面管理器**。该模块负责直接与物理磁盘文件（.db, .prp 等）交互，并维护一个高效的内存页面缓存池。

## 2. 核心函数分析表

以下是已映射并在 IDA Pro 中重命名的函数列表，这些函数是解析数据库存储格式的关键入口点。

| :--- | :--- | :--- | :--- |

| **`db1_read_page`** | `0x10630C00` | 磁盘读取 | 调用系统 `ReadFile` 从指定偏移读取原始页数据。 |

## 3. 架构设计分析

### 3.1 页面调度流程
当上层模块需要访问 E3D 元素属性时，调用链路如下：
`上层业务 -> DB_Access -> db1_get_page -> db1_read_page -> OS I/O`

### 3.2 逆向建议
- **数据结构**: `db1_get_page` 的第一个和第二个参数通常是 `dbno` (数据库编号) 和 `pgid` (逻辑页号)。
- **页面大小**: 通过 `db1_read_page` 的内存分配大小可以推断 PDMS 页面大小（通常为 2048 或 4096 字节）。
- **同步机制**: 关注 `db1_update_page` 之后的 `db1_write_page` 调用时机，可分析出事务提交（Commit）的触发点。

## 4. 结论

`db1` 模块是 PDMS 数据库的“心脏”。所有的物理 I/O 和缓存一致性都由此模块保证。目前各函数已在 IDA 中完成重命名，并添加了中文注释。
